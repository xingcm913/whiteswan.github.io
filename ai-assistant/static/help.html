一、快速开始（3 步用起来）

  1. 打开右上角「⚙ 设置」，填写：
    • 上游 Base URL（推荐智谱 GLM：https://open.bigmodel.cn/api/paas/v4/）
    • 上游模型（如 glm-4-plus）
    • 上游 API Key（在对应平台注册后获取，sk-...）
    • 默认系统提示词
    保存即可。
  2. 在中间对话框输入内容，按 Ctrl+Enter 或点击「发送」。
  3. 如果想给别人用：打开右上角「🔑 API Key」创建一个 Key，把 base_url + api_key 给对方即可（见第六节）。
本服务是一个应用层：真正的 AI 能力来自你填写的上游模型 API。 所以你不需要 GPU、不需要训练大模型 —— 上游已经训练好了，本服务负责参数调节、训练样本注入、API Key 分发与时间修正。

二、AI 训练：让模型按你的方式回答

2.1 这里的"训练"是什么

本服务的"训练"是提示词注入式软训练（in-context learning）， 不是从零训练一个新模型（那需要 GPU 集群）。具体做法：你写的每条"训练样本" 在每次对话时都会被自动拼到系统提示词里，模型会按你设定的风格、规则、 人设、知识来回答。改完立即生效，无需重启。

2.2 三种样本角色

角色用途示例
system规则/约束/人设，模型必须遵守"回答必须分点列出"
user示例问题（输入）"帮我写周报"
assistant示例回答（输出），告诉模型该这么答"# 本周工作……\n1. …"

配对使用 user+assistant（few-shot）效果最好。 system 类样本适合放硬规则。

2.3 怎么添加训练样本

  1. 点右上角「📚 训练」
  2. 选择角色（system / user / assistant）
  3. 填分组标签（可选，方便管理，比如 周报风格）
  4. 填内容，点「添加」
开关「注入训练样本」可临时关闭训练（仍保留样本数据），下次打开又生效。

三、训练文本怎么写（含完整示例）

3.1 写得好的原则

  • 具体：不要写"态度好一点"，要写"回答开头先复述用户问题，结尾问一句'是否还需要补充'"。
  • 可验证：写得出就能判断对错，比如"输出格式必须为 Markdown 表格"。
  • 给反例：告诉模型不要做什么，比只告诉它要做什么更有效。
  • 给例子：一条 user+assistant 配对样本，胜过十句抽象指令。

3.2 完整示例 1：把 AI 调教成"周报助手"

依次添加以下 3 条样本：

样本 ①（system 规则）

你是一个专业的"周报助手"。请严格遵守：
1. 输出固定使用 Markdown 格式
2. 结构必须是：## 本周工作 / ## 遇到问题 / ## 下周计划
3. 每条工作前用 "-" 列表，每条不超过 30 字
4. 不要寒暄、不要问"需要我做什么"，直接给报告
5. 如果用户输入太短，请基于已知信息合理扩写，但不得编造具体数字

样本 ②（user 示例）

本周做了登录模块联调，修了 2 个 bug，下周要做权限管理

样本 ③（assistant 示例，对应样本②的回答）

## 本周工作
- 登录模块前后端联调完成
- 修复 2 个已知 bug

## 遇到问题
- 联调过程中接口字段对齐耗时较长

## 下周计划
- 启动权限管理模块开发
- 完成接口设计评审
把 ②③ 配成一对，模型就学会了"输入这种乱糟糟的话 → 输出这种结构化报告"。 下次用户随便说几句，AI 也会自动按这个格式答。

3.3 完整示例 2：把 AI 调教成"客服话术"

[system] 你是某品牌客服。规则：
1. 永远先共情："非常抱歉给您带来困扰"
2. 不确定的事不要承诺，改说"我帮您核实后回复您"
3. 涉及退款/赔偿，必须先问订单号
4. 全程用"您"，不用"你"

[user] 你们东西坏了！退款！

[assistant] 非常抱歉给您带来困扰，理解您的心情。
为了帮您处理退款，请您提供一下订单号，我核实后立即为您处理。

3.4 完整示例 3：让 AI 永远答对"现在是几几年"

[system] 关于时间：系统提示词里已包含真实当前时间。
当用户问"现在几几年/几月几号/星期几"时，必须用系统时间作答，
绝对不能说 2024 年、不能编造日期。
其实只要打开"注入系统时间"开关，模型就已经能看到真实时间了。 上面这条样本只是再加强一次"必须用真实时间"的硬约束。

3.5 常见"训练"模板速查

目标样本写法
固定输出格式system: "输出必须是 JSON，字段为 {summary, tags}"
语气控制system: "用幽默的语气，每段结尾加一个 Emoji"
限定领域system: "只回答编程问题，非编程问题回复'我只能聊编程'"
few-shot 问答user: "输入示例" + assistant: "想要的输出示例"
禁止 hallucinationsystem: "不知道就说不知道，不要编造"

四、参数调节详解

参数范围作用推荐值
temperature0 ~ 2越高越随机有创意，越低越确定严谨创意 1.1 / 平衡 0.7 / 严谨 0.2
top_p0 ~ 1核采样，与 temperature 二选一调节0.9
max_tokens64 ~ 32768回答最大长度2048
presence_penalty-2 ~ 2正值鼓励谈新话题0
frequency_penalty-2 ~ 2正值降低重复用词0
system_prompt文本人设/全局指令按需

参数面板里可「存为预设」一键切换：比如存一个"创意""严谨"预设，按需应用。

五、为什么问"现在是几几年"会答对

大模型本身有"知识截止时间"，所以你直接问"今天几号"它可能答 2024 年。 本服务做了两件事修复这个问题：

  1. 每次对话都把真实系统时间（含年月日时分秒、星期、ISO 格式）拼进系统提示词。
  2. 用一段硬指令告诉模型：遇到时间问题必须用这个时间回答，不要用训练数据里的旧时间。

开关在左侧面板「注入系统时间」，默认开启。

六、创建 API Key

  1. 右上角「🔑 API Key」→ 输入名称 → 「创建」
  2. 得到形如 sk-assistant-xxxx... 的 Key
  3. 可随时启用/停用/删除
API Key 是别人调用你服务的凭证，请妥善保管，不要泄露到公开仓库。

七、外部软件接入（OpenAI 兼容）

本服务暴露的接口完全兼容 OpenAI 协议，凡是支持自定义 base_url 的客户端都能接。

7.1 通用配置

Base URL:  http://<你的服务器IP>:8000/v1
API Key:   在第六节创建的 sk-assistant-xxx
Endpoint:  POST /v1/chat/completions
模型名:    任意填（本服务会用设置里的"上游模型"）

7.2 Python 调用示例

from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="sk-assistant-你的key",
)

resp = client.chat.completions.create(
    model="any",
    messages=[
        {"role": "system", "content": "你是一个简洁的助手"},
        {"role": "user", "content": "现在几几年几月几号？"},
    ],
)
print(resp.choices[0].message.content)

7.3 curl 调用示例

curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer sk-assistant-你的key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "any",
    "messages": [{"role":"user","content":"你好"}],
    "stream": false
  }'

八、常见问题

Q1: 启动后聊天报错"尚未配置上游模型 API Key"

去右上角「⚙ 设置」填上游 API Key（来自智谱/OpenAI 等），保存。

Q2: 问"现在几号"还是答 2024 年？

检查左侧面板「注入系统时间」是否开启；同时点顶部「⏱ 时间」确认服务端时间正确。也可加一条训练样本强化（见 3.4）。

Q3: 训练样本越多越好吗？

不是。样本太多会让系统提示词过长、拖慢响应、还可能互相冲突。建议 5~30 条精选样本即可。

Q4: 想让模型记住某个人设？

两种方式：①在设置里改"默认系统提示词"；②加一条 system 类训练样本。效果叠加。

Q5: 对外的 API Key 调用次数限制？

本服务完全免费，不限制次数。但你调用上游模型（如智谱）的额度受上游平台限制。

Q6: 数据存在哪？

SQLite 文件 data/assistant.db，跟着项目走，可备份/迁移。
